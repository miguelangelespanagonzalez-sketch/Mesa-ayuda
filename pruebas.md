# 📋 Tabla de Pruebas

Este documento registra las pruebas manuales realizadas a los endpoints de la API del sistema de tickets por el equipo de desarrollo y soporte (Miguel Ángel España, Lorenzo González y Santiago Ocampo).

| Endpoint                      | Caso / Tipo de Prueba          | Entrada Usada (Request)                                                                                                                    | Resultado Esperado                                                                    | Resultado Obtenido                                                               | ¿Pasó? |
| :---------------------------- | :----------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------- | :----- |
| `GET /tickets/tecnicos`       | **Camino feliz**               | Ninguna (Petición GET directa)                                                                                                             | Retornar la lista de técnicos registrados con código `200`.                           | Lista de técnicos en formato JSON con código `200`.                              | **Sí** |
| `GET /tickets`                | **Camino feliz**               | Ninguna                                                                                                                                    | Retornar la lista de todos los tickets existentes con código `200`.                   | Arreglo JSON con los tickets activos (código `200`).                             | **Sí** |
| `POST /tickets`               | **Camino feliz**               | `{"titulo": "Falla en Red", "descripcion": "Switch principal sin energía", "prioridad": "alta", "tecnicoAsignado": "Miguel Ángel España"}` | Crear el ticket exitosamente con ID autoincremental, estado 'abierto' y código `201`. | Ticket creado correctamente con ID, fecha y código `201`.                        | **Sí** |
| `POST /tickets`               | **Datos incompletos**          | `{"descripcion": "Falta el título obligatoriamente"}`                                                                                      | Rechazar la petición con código `400` y un mensaje claro de error.                    | Respuesta `400` indicando que el título es obligatorio sin colapsar el servidor. | **Sí** |
| `GET /tickets/:id`            | **Camino feliz**               | ID existente: `1`                                                                                                                          | Retornar el detalle completo del ticket solicitado con código `200`.                  | Datos exactos del ticket `1` con código `200`.                                   | **Sí** |
| `GET /tickets/:id`            | **ID inexistente**             | ID: `999`                                                                                                                                  | Retornar código `404` con mensaje de error "Ticket no encontrado".                    | Respuesta `404` con el mensaje JSON especificado.                                | **Sí** |
| `PUT /tickets/:id`            | **Camino feliz**               | ID: `1`, Body: `{"estado": "en proceso", "prioridad": "alta"}`                                                                             | Actualizar los campos del ticket y retornar el objeto modificado con código `200`.    | Ticket actualizado correctamente con código `200`.                               | **Sí** |
| `PUT /tickets/:id`            | **ID inexistente**             | ID: `999`, Body: `{"estado": "cerrado"}`                                                                                                   | Retornar código `404` indicando que no se encontró para actualizar.                   | Respuesta `404` con error de ticket no encontrado.                               | **Sí** |
| `GET /tickets?estado=abierto` | **Regla de negocio / Filtros** | Query param: `?estado=abierto`                                                                                                             | Filtrar y retornar únicamente los tickets que tengan el estado 'abierto'.             | Arreglo filtrado correctamente con los tickets abiertos.                         | **Sí** |
| `DELETE /tickets/:id`         | **Camino feliz**               | ID existente: `1`                                                                                                                          | Eliminar el registro del arreglo en memoria y retornar código `204` (Sin contenido).  | Eliminación exitosa con respuesta vacía y código `204`.                          | **Sí** |
| `DELETE /tickets/:id`         | **ID inexistente**             | ID: `999`                                                                                                                                  | Retornar código `404` indicando que no existe el ticket a eliminar.                   | Respuesta `404` con error claro.                                                 | **Sí** |
